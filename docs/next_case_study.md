# Adding a new case study — 30-minute checklist

This portfolio is built to keep growing after the internship ends. Adding
a new case here should be a short conversation with the existing Claude
Project, not a rebuild. This file is the habit that makes that true.

## The shape (reused from Week 2)

Every case study on the Work page follows the same three beats:

1. **Problem** — what real question or task this project answers, in one
   or two sentences.
2. **What I did** — the actual approach, named plainly (e.g. "chronological
   split instead of shuffled" for the COVID case). No adjectives without a
   number behind them.
3. **What came of it** — the real result, including the honest before/after
   if there is one (e.g. R² 0.901 → 0.629). If the result is negative or
   partial, say so — that's the proof of honest evaluation this whole site
   exists to demonstrate.

## Steps, in order

1. **Open the existing Claude Project** for this portfolio — it already
   holds the proof statement, voice card, and identity kit. Don't start a
   new chat from scratch.
2. **Paste the raw material**: notebook, README, or repo link for the new
   project.
3. **Ask for the three-beat draft**, explicitly in the site's existing
   voice (quiet confidence, no hype, numbers over adjectives). One prompt,
   one draft — this project's whole track record shows this takes a
   conversation, not a rebuild.
4. **Push back on anything vague** the draft produces, the same way every
   case on this site so far has been pressure-tested — if a claim doesn't
   have a number behind it, cut it or fix it.
5. **Add it to the Work page** as a new entry, following the existing
   layout and identity kit (IBM Plex Sans/Mono, #B45309 accent) — don't
   introduce a new visual style per case.
6. **Real screenshot or evidence**, if the case has one (a leakage check
   table, a before/after metric) — same standard as the rest of the site:
   real artifacts, not invented ones.
7. **Commit and push.** Done.
